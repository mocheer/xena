# raster 地图网格设计

数据存在数据库，但访问时自动缓存到本地，编译时自动打包，开发时有三种状态，纯数据库、纯本地文件，数据库+本地文件混合，编译时只支持本地文件打包

用户端的数据，如果是单机版本，那就只保留到本地（根据场景id+状态信息），并进行加密

## 设计

服务端：

0. 地图场景id+栅格数据+场景信息

1. 初始化 8BUI ，支持0-256个值，多通道设计
2. 场景信息：通道信息映射，0-256映射出对应的纹理资源、模型资源、角色资源的id，并提供场景+物品的初始化状态（不同场景下的资源，初始信息和初始状态不同，这个其实是用户态之前的默认状态，可直接利用用户态的数据）、是否支持光影，场景的链接信息，用户的初始位置（一个场景会链接其他场景，这里提供进入下一个场景的id（多个），然后场景地图中的门是一个范围触发器，并且在场景信息中保存对应的链接序号，一旦进入，就会触发场景切换），包括场景音乐
3. 通道一：纹理映射，包括草地、沼泽、砖块等纹理用作地形映射，
4. 通道二：模型映射，包括建筑物、房屋、墙壁等模型映射，覆盖地形，和地形同时存在，设置复杂模型时有网格范围及其高度信息，覆盖纹理映射的高度信息，类似城门，一旦打开，理应支持通行,有些建筑物是机关，是有一套内置程序运行的
5. 通道三：角色映射，包括角色、Boss、小怪的映射，覆盖地形和模型映射，在他们之上，有一套傻瓜式AI来自动操作，角色所在位置不可通行

素材端：
0. 素材id+素材数据+素材信息
1. 模型id + 素材id + 模型信息（AI 机制+初始化状态）
2. 智能体：多指令集合，指令ID，比如说对话任务，发布任务，场景跳转等，同一时刻可以有多个指令监听运行，并存储具体指令执行的内容，根据用户状态，来监听和执行有效的指令

用户端：

每个地图下的模型物品都有一个唯一id（当需要交互时，一般用模型id），保存用户态的信息，用于状态交互，比如说开锁后，门消失了（隐藏），宝箱开启后，宝箱处于开启状态。每进入一个场景地图，除了加载场景数据，还需要加载用户态数据


加载多通道时，生成临时状态下的高度映射信息表+指令监听集，用于在地形+模型之上渲染角色位置，可以快速查询一个坐标下是否可同行。比如说查询 5，5坐标下，可同行的高度为2、8、10，如果当前角色位置在1，那可以通过跳跃进入2，如果位置在2，则可以走进去。如果有城门，那么城门对应的网格位置均不可同行,城门打开时可通行，如果有城门守卫，则城门打开也不一定可同行，根据用户状态，比如说有通行证才可以行走

1. 空值不可通行
2. 高度值支持浮点数（地形和模型的高度支持浮点值，有高度起伏效果，角色进入后需要在上面）


特殊场景：绳索，可移动的跳板，需要专门编写对应的逻辑，监听对应的事件。

跳板：监听位置和角色位置，修改默认的高度映射，当角色移动到当前位置，根据时间自动修改角色位置
绳索：监听位置是否重叠，如果重叠，则角色可向上攀爬
